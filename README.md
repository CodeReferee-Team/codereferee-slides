# CodeReferee 기말 발표 자료

2026-11-17(화) 18:00 T802 기말 발표용 슬라이드와 대본이다. 팀별 10분, 프로젝트를 처음 보는 청중 대상.

- **발표 자료**: https://codereferee-slides.vercel.app
- **레포**: https://github.com/CodeReferee-Team/codereferee-slides

발표 자료는 이 주소 하나로 본다. HTML 파일을 카톡으로 주고받지 않는다.
`main`에 push하면 1분 안팎으로 위 주소가 자동 갱신된다.

## 기본 조작

| 키 | 동작 |
| --- | --- |
| → / 스페이스 / 화면 클릭 | 다음 |
| ← | 이전 |
| F | 전체화면 |
| **P** | **발표자 창 열기** |
| N | 슬라이드 아래에 노트 표시 (빔에도 보이니 발표 중에는 쓰지 않는다) |

## 발표자 기능

빔에는 슬라이드만 나오고, 노트북에는 대본과 타이머가 보인다.

### 발표자 창에 보이는 것

- 지금 빔에 나오는 슬라이드 (애니메이션까지 같이 움직인다)
- 대본: **지금 읽을 부분은 흰색 굵은 글씨**, 지난 부분은 흐리게, 남은 부분은 회색
- 대본의 `[→]`: 여기서 → 키를 누른다
- 타이머: 발표 시작부터 흐른 시간. 그 슬라이드의 계획 시간을 넘기면 빨간색
- 슬라이드 번호, 단계, 다음 장 제목
- 이전 / 다음 / 타이머 0 버튼

### 발표 당일 순서

1. 노트북과 빔을 연결하고 **`Win + P` → 확장**을 고른다. "복제"를 고르면 대본이 빔에도 나온다
2. 크롬에서 https://codereferee-slides.vercel.app 을 연다
3. **`P`** 를 누르면 발표자 창이 새로 열린다
4. **슬라이드 창**은 빔 화면으로 끌어다 놓고 **`F`** 로 전체화면
5. **발표자 창**은 노트북 화면에 둔다
6. 발표자 창에서 **→ 키나 "다음" 버튼**으로 넘긴다. 빔 화면도 같이 넘어간다
7. 시작할 때 **"타이머 0"** 을 눌러 0부터 잰다

### 주의

- 두 창은 같은 주소에서 열어야 연결된다. 슬라이드 창에서 `P`로 발표자 창을 연다
- 발표자 창을 실수로 닫아도 `P`를 다시 누르면 현재 위치부터 이어진다
- HTML 파일을 더블클릭해서 열면 발표자 창이 연결되지 않을 수 있다
- 실제로 쓸 노트북과 빔으로 미리 한 번 시험해 본다

### 인터넷이 안 될 때

레포를 노트북에 받아 두고 그 폴더에서 실행한다.

```bash
python -m http.server 8765
```

http://127.0.0.1:8765/ 을 열고 위와 똑같이 `P`를 누른다. 인터넷 없이도 발표자 기능이 동작한다.

## 발표 자료 고치는 법

| 고칠 것 | 파일 |
| --- | --- |
| 슬라이드 화면 | `index.html` |
| 대본, 예상 질문 | `script.md` |

`script.md`의 대본은 발표자 창에 자동으로 들어간다.
고치기 전에 단톡에 **"○번 슬라이드 고칠게"** 남기고, 수치는 출처가 확인된 것만 넣는다.

```bash
git pull
# index.html 또는 script.md 수정
python tools/sync_script.py   # 대본을 발표자 노트에 반영 + [→] 개수·대본 길이 확인
git commit -am "7번 슬라이드 대본 수정"
git push                      # 1분 뒤 발표 주소에 반영
```

`python tools/sync_script.py`를 빼먹어도 push 후 GitHub Actions가 반영해 커밋한다. 다음에 고치기 전에 `git pull`로 받아 온다.

대본 쓰는 법:

- `## 7. 검증 워크플로우`처럼 제목 번호는 슬라이드 순서와 같다
- `[→]`는 → 키를 누를 자리다. 넘기는 단계를 바꿀 때만 개수를 맞추면 된다
- `(3:05~3:35)`는 발표자 창 타이머 기준 시간이다
- `index.html` 안의 `<aside class="notes">`는 `script.md`로 덮어써진다. 대본은 거기서 고치지 않는다

### index.html 고칠 때 꼭 지킬 세 가지

**1. 슬라이드 하나는 이 틀을 따른다.** 대본 자리 `<aside class="notes">`는 비워 둔다. `script.md` 대본이 자동으로 들어간다.

```html
<section class="slide" id="s17" data-title="새 슬라이드">
  ... 화면 내용 ...
  <aside class="notes"></aside>
</section>
```

**2. 슬라이드를 추가, 삭제하거나 순서를 바꾸면 `script.md`도 같이 맞춘다.** `## N. 제목`의 개수와 순서가 슬라이드와 같아야 한다. 다르면 대본이 반영되지 않는다.

**3. 이미지는 `assets/`에 파일로 넣고 `assets/파일명`으로 쓴다.** HTML 안에 통째로 넣지 않는다. 다른 HTML 파일로 `index.html`을 통째로 덮어쓰지 않고, 바뀐 슬라이드만 옮긴다.

## 파일 구조

| 파일 | 내용 |
| --- | --- |
| `index.html` | 슬라이드 16장, 애니메이션, 발표자 기능 |
| `script.md` | 대본, 시간이 넘칠 때 줄이는 순서, 예상 질문 |
| `assets/` | 폰트, 기술 로고, 데모 캡처 |
| `tools/sync_script.py` | `script.md` 대본을 `index.html` 발표자 노트에 넣고 검사 |
| `.github/workflows/sync-script.yml` | push 때 위 스크립트를 실행해 커밋 |
